Documentation

How a question becomes an answer.

The language model's job is deliberately narrow: read the retrieved evidence and write an answer grounded in it. It is designed not to introduce fabricated citations — citation accuracy is enforced by a separate post-processing step, not by the model's judgment — and when retrieval doesn't surface adequate evidence, the system abstains. Citation resolution does not by itself guarantee that every generated interpretation is fully supported by the underlying passage; claim-level grounding remains subject to ongoing evaluation.

The pipeline

  1. 01

    Ingestion & curation

    Papers are collected from approved open-access sources according to the project's ingestion and licensing criteria, deduplicated, and split into passages.
  2. 02

    Embedding

    Each passage is converted into a vector using OpenAI's text-embedding-3-large.
  3. 03

    Indexing

    Those vectors are stored in a FAISS index built for fast similarity search.
  4. 04

    Retrieval

    An incoming question is embedded and matched against the index to pull the most relevant passages.
  5. 05

    Generation

    A fine-tuned language model composes an answer using only the retrieved evidence.
  6. 06

    Citation resolution

    Generated citations are resolved against canonical records in the corpus during post-processing. Citations without a valid corpus match are rejected rather than shown.
  7. 07

    Abstention

    If the evidence isn't strong enough, the system says so instead of manufacturing an answer.

The system today

Model
Qwen2.5-32B-Instruct with a fine-tuned LoRA adapter
Embeddings
OpenAI text-embedding-3-large
Retrieval
FAISS over 338,701 deduplicated passages drawn from roughly 13,387 papers — see the corpus →
Citations
Generated citations are resolved against canonical records in the corpus; citations without a valid corpus match are rejected during post-processing. This verifies that a cited source exists and is correctly attributed — it does not by itself guarantee that every generated interpretation of that source is fully supported
Interface
A hosted web frontend

This is the current proof-of-concept build. The corpus is deliberately frozen during validation and is designed to scale substantially once that window closes.

    Explore a potential clinical pilot with academic medical collaborators, subject to approval and funding.

Abstention is not an error — it's a feature. When AskStein says it doesn't know, it's reporting the honest boundary of what its corpus contains, not failing to answer.
